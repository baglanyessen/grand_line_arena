# Grand Line Arena

Шахматы во вселенной One Piece: Морской дозор играет белыми, пираты — чёрными. Вместо привычного рейтинга в интерфейсе используется награда за голову — bounty. Игроки объединяются в команды, участвуют в войнах и могут вызвать капитана на серию партий за лидерство.

## Возможности

- **Play chess — главная страница.** Гость может играть за обе стороны на локальной доске. Для поиска соперника нужно войти в аккаунт. Отдельное лобби удалено; логотип возвращает к игре.
- **Сетевая игра:** поиск соперника, контроль 5+0, превращение пешки, сдача, предложение ничьей, восстановление после обрыва связи и сохранение результатов.
- **Play with bot:** Stockfish, три уровня силы, выбор цвета, отмена ходов, подсказки и наставник на русском или английском. Эти партии не меняют bounty.
- **Training deck:** 20 задач, 54 линии дебютов, 16 позиций эндшпиля и разбор ошибок из сохранённых партий, текущей игры с ботом или вставленного PGN.
- **Engine chat:** анализ позиции, угрозы, рекомендуемый ход и разбор своего хода. Карточки могут показывать стрелки и выделения на соответствующей позиции.
- **AI chat:** вопросы наставнику и уточнения с контекстом разговора. ИИ объясняет позицию, но не двигает фигуры.
- **Crew quarters:** создание команды, поиск, вступление, роли, передача капитанства, войны и вызов капитана.
- **Captain’s log:** история собственных партий, просмотр ходов и скачивание PGN.
- **Wanted board:** таблица игроков по bounty.

## Стек и структура

Клиент: React 19, Vite, Tailwind, react-chessboard, chess.js и Lucide. Сервер: Bun, Elysia, TypeScript, Drizzle и PostgreSQL. Stockfish.js запускается сервером в отдельном процессе Node.js. Текстовый наставник использует OpenAI Responses API.

```text
src/
  App.jsx                 Навигация; начальная страница — Play
  components/             Доска, бот, тренировки, команды и история
  components/Adventure.css Общая тема One Piece
  hooks/                  Локальная игра, WebSocket и игра с ботом
  lib/                    API, синхронизация, часы и упражнения
  data/training/          Каталог упражнений и аудит импорта
server/
  src/index.ts            Точка входа сервера
  src/routes/             HTTP API
  src/ws/                 Сетевые партии, часы и сроки командных событий
  src/db/                 Схема, миграции и транзакционные операции
  src/bot/                Stockfish, выбор уроков и OpenAI
  scripts/                Миграции и проверка в браузере
public/licenses/          Лицензия заимствованного учебного контента
```

## Установка

Нужны Node.js с npm, Bun и работающий PostgreSQL. Команды ниже выполняются из корня проекта, если явно не указана другая папка. В PowerShell при блокировке `npm` политикой выполнения используйте `npm.cmd`.

```powershell
npm install
cd server
bun install
Copy-Item .env.example .env
```

Создайте базу PostgreSQL, например `grand_line_arena`, и заполните `server/.env`:

```dotenv
DATABASE_URL=postgres://postgres:password@localhost:5432/grand_line_arena
JWT_SECRET=длинный-случайный-секрет
OPENAI_API_KEY=
OPENAI_COACH_MODEL=gpt-4.1-mini
```

Ключ OpenAI нужен для текстового наставника. Stockfish и engine chat работают без него. Ключ хранится только на сервере: не добавляйте его в переменные с префиксом `VITE_` и не коммитьте `.env`. После изменения настроек перезапустите сервер. В production требуется собственный надёжный JWT-секрет.

Для новой локальной базы примените схему из папки `server/`:

```powershell
bun run db:push
```

Для обновления существующей базы предусмотрены отдельные миграции. Остановите сервер перед миграцией активных партий, поскольку она получает эксклюзивное владение игровым движком. Перед изменением базы с реальными данными сделайте резервную копию и проверьте изменения схемы.

```powershell
bun run db:migrate:bounty
bun run db:migrate:crews
bun run db:migrate:crew-archive
bun run db:migrate:war-rosters
bun run db:migrate:war-settlement
bun run db:migrate:war-deadlines
bun run db:migrate:active-games
bun run db:migrate:leadership
```

`db:push` предназначен для локальной разработки. Для развёртывания изменения схемы нужно проверять и применять контролируемо; `db:generate` доступен для генерации миграций Drizzle.

## Запуск

В первом терминале, из корня:

```powershell
npm run dev
```

Во втором терминале:

```powershell
cd server
bun run dev
```

Клиент обычно доступен на `http://localhost:5173`, API — `http://localhost:3001`, WebSocket — `ws://localhost:3001/ws/chess`. Для запуска сервера без режима наблюдения используйте `bun run start` из `server/`.

Сборка клиента: `npm run build`; локальный просмотр сборки: `npm run preview`.

Порт сервера задаётся переменной `PORT`. Адреса клиента настраиваются через `VITE_API_URL` и `VITE_WS_URL` при запуске Vite или сборке. Допустимые источники CORS пока перечислены в `server/src/index.ts`; домен развёрнутого клиента нужно добавить туда.

Stockfish установлен в корневых зависимостях. Для нестандартного размещения доступны `STOCKFISH_JS_PATH` и `NODE_BINARY`. Рядом с JS-файлом движка должен находиться соответствующий WASM-файл.

## Как работает сетевая партия

Сервер проверяет JWT и загружает аккаунт из базы. Переданный клиентом идентификатор игрока не определяет его личность. Повторное активное соединение одного аккаунта отклоняется; срок действия токена проверяется при командах.

Клиент отправляет ход с идентификатором запроса и версией позиции. Сервер проверяет очередь хода, легальность, часы и актуальность версии. Онлайн-доска меняется после подтверждения сервера. Повторная доставка запроса не применяет ход второй раз; устаревший клиент получает текущее состояние.

Снимок содержит FEN, PGN, участников, версию, часы, предложение ничьей и привязку к войне или серии за капитанство. PGN сохраняет историю, необходимую для повторений и просмотра партии. Превращение пешки требует явного выбора фигуры.

Контроль времени — 5 минут без добавления. Время считает сервер. При обрыве связи часы продолжают идти, а игрок получает 30 секунд на возвращение. Отсутствие одного игрока заканчивается поражением по отключению; отсутствие обоих — ничьей по принятой политике проекта. После перезапуска простой также списывается с часов; восстановление не должно каждый раз продлевать старый срок отключения.

Активные партии и записи, ожидающие завершения, хранятся в PostgreSQL. Завершённая партия, bounty и результат командного матча фиксируются транзакционно и идемпотентно: повторная обработка не создаёт второй результат или вторую награду. Уведомление об окончании отправляется после сохранения.

Таблицы `active_games`, `active_game_players` и `active_engine_owner` обеспечивают восстановление и владение движком. PostgreSQL допускает один авторитетный игровой процесс на схему; версии снимков и поколения владельца защищают от устаревших записей. Второй игровой сервер с той же схемой намеренно не запускается как независимый владелец.

Папка `server/.data/` нужна только для совместимости со старыми файловыми сохранениями и тестовых адаптеров. Обычная работа сервера больше не зависит от неё. Миграция активных партий переносит старые файлы в PostgreSQL, предварительно создавая резервные копии. Для этого импорта доступны `ACTIVE_GAMES_DIR`, `GAME_RESULTS_DIR` и `ACTIVE_IMPORT_BACKUP_DIR`. Базу PostgreSQL и её резервные копии необходимо сохранять независимо от перезапусков приложения.

## Bounty, команды и капитанство

Обычная победа даёт +100 bounty, поражение снимает до 50, ничья не меняет награду. Минимум — 0, максимум — 1 триллион. Для награды нужна решающая партия минимум из четырёх полуходов. Одна пара игроков может получить bounty за три решающие партии в сутки UTC. Старые партии не оплачиваются задним числом.

Игрок состоит только в одной команде. В команде один капитан; доступны роли офицера и участника. Капитан управляет ролями и может передать лидерство текущему участнику. Бывший капитан становится офицером. Расформирование архивирует команду и сохраняет исторические ссылки; открытые командные события блокируют несовместимые изменения состава.

Война начинается с вызова и согласия второго капитана. Капитаны выбирают упорядоченные составы; после обоих составов создаются пары с чередованием цветов. Победа на доске приносит 1 очко, ничья — 0,5. Счёт и ссылки на партии сохраняются вместе с результатом.

Бонус победившим бойцам — до +200 bounty, при ничьей войны — до +100; проигравшим — 0. Для бонуса все доски должны содержать минимум четыре полухода. Для одной пары команд предусмотрен один бонус войны за сутки UTC. Уникальные записи выплат защищают от дублирования.

На ответ на вызов, подачу составов и вход в назначенные партии действуют сроки по 24 часа. Фоновый обработчик проверяет их каждые 30 секунд. Неявки и прерывания дают технические исходы без выдуманного PGN; войны с технической победой не дают бонус войны.

Участник может вызвать капитана на серию максимум из трёх партий. Капитан должен согласиться; первый цвет вызывающего — белый, затем цвета чередуются. Победа — 1 очко, ничья — 0,5. Два очка завершают серию досрочно; после третьей партии выигрывает набравший больше очков. При равенстве капитан сохраняет должность. Смена капитана, роли, решающая партия и её bounty фиксируются одной транзакцией. Повторный вызов от одного участника ограничен 24 часами; война и серия за капитанство не проходят одновременно.

## Бот и наставник

Stockfish выбирает ходы и оценивает позиции; chess.js проверяет легальность. Текстовый ИИ получает очищенную позицию, короткий вариант движка и вычисленные факты. Передача PGN удаляет посторонние комментарии и заголовки. Учебные позиции с собственным FEN проходят отдельную проверку; обычная игра с ботом сохраняет ограничение стандартной начальной позиции.

Автоматические объяснения появляются при конкретном событии: шахе, вилке, незащищённой фигуре, связке с королём или перекрытой диагонали собственного слона. В обычных позициях наставник молчит, а недавние повторные уроки пропускаются до обращения к OpenAI. Цель ответа — одна-две короткие фразы о понятном последствии хода. Ручные подсказки и вопросы доступны отдельно.

Engine chat не обращается к OpenAI. AI chat отправляет текущий контекст и до десяти сообщений разговора через сервер. Запросы используют `store: false`; API-ключ, имена пользователей и адреса электронной почты не включаются в шахматный контекст. Это настройка хранения ответа API, а не обещание полного отсутствия обработки данных провайдером.

Без доступного ИИ подсказка помечается как **Engine tip**. AI chat показывает ошибку доступности и не выдаёт заготовку за реальный ответ ИИ. Текст наставника может ошибаться; решения о легальности ходов от него не зависят.

Лимиты на аккаунт: 40 запросов движка и 8 некэшированных запросов наставника в минуту. Одновременно допускаются два поиска движка и две задачи наставника. Есть тайм-ауты и ограниченный кэш объяснений на 10 минут. Эти ограничения действуют в памяти одного процесса, а не на всё распределённое развёртывание.

Позиция игры с ботом и разговор сохраняются в `sessionStorage` текущей вкладки; прогресс упражнений — в `localStorage` этого устройства. Это не серверный профиль обучения. Разбор ошибок проверяет до шести собственных ходов за пакет; короткий поиск находит возможные ошибки, но не даёт гарантированно точную оценку качества всех ходов. Тренировки не меняют соревновательную историю и bounty.

## Проверки

Из корня проекта:

```powershell
npm test
npm run build
npm run test:browser
```

Из папки `server/`:

```powershell
bun run typecheck
bun run test
bun run test:postgres
```

Проверки PostgreSQL создают отдельную временную схему и удаляют её после завершения. Браузерный сценарий также использует изолированную схему и тестовые аккаунты. Нужны доступный PostgreSQL с подготовленной схемой, Node, Bun и установленный Chrome/Edge; путь к браузеру можно задать через `BROWSER_TEST_EXECUTABLE`.

Браузерный сценарий запускает тестовый API на порту 3301 и клиент на `127.0.0.1:5173`, проверяет маршрутизацию, регистрацию, движок, тренировки, партии двух игроков, капитанство, войны и историю. Занятые тестовые порты нужно освободить. Отчёты, логи и снимки создаются в игнорируемой папке `artifacts/browser-acceptance/`.

Обычный браузерный тест не вызывает платный OpenAI API. Для проверки реального наставника из корня в PowerShell:

```powershell
$env:BROWSER_TEST_BOT_ONLY='1'
$env:BROWSER_TEST_LIVE_COACH='1'
bun --env-file=server/.env run server/scripts/browser-acceptance.ts
Remove-Item Env:BROWSER_TEST_BOT_ONLY
Remove-Item Env:BROWSER_TEST_LIVE_COACH
```

Этот режим делает реальные платные запросы с серверным ключом. Набор проверок включает 83 серверных, 69 интеграционных тестов PostgreSQL и 31 клиентский тест. Браузерная проверка дополняет их реальными действиями, но не заменяет проверку всех шахматных случаев.

## Что осталось перед production

- Настроить домены, HTTPS/WSS, CORS, секреты, резервное копирование и мониторинг PostgreSQL.
- Добавить ограничения запросов на регистрацию, вход и поиск соперников; общие квоты и бюджеты OpenAI для развёртывания.
- Настроить воспроизводимые миграции и автоматический запуск проверок в CI.
- Расширить браузерные сценарии: превращения, ничьи, войны на нескольких досках и другие браузеры.
- Уточнить adjudication по времени для сложных позиций: сейчас есть исключение для голого короля, но нет полной проверки возможности мата для любой позиции.
- Для нескольких игровых серверов спроектировать распределённую маршрутизацию и владение партиями; текущий механизм рассчитан на одного владельца схемы.
- При необходимости добавить публичные профили и серверное хранение учебного прогресса.
